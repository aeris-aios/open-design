## D. 产品裁决 · 落块规则(2026-08-26,用户口述)

> 原话:「这里有两张展开收起卡片,但是第一张卡片那边还没有产生 todo,那这部分收起的应该

- 这条**收紧了 D43**(原来是「done 之前的过程叙述画在壳里」)——
  现在「过程叙述」在**没有 todo 的阶段属于壳外**。
- **thinking 不受影响**:它任何阶段都在壳里(与稿子第 2 格的 `<p class="think">` 一致)。
- 待确认的一点:第 1 阶段「普通文本放外面」指的是**模型的正文输出**,
  不含 thinking —— 我按这个理解实现。

## D-final. 落块裁决(2026-08-26 最终版,推翻同日两条中间裁决)

用户原话,分两次给:

> 「没有 todowrite 时,所有工具调用或普通文本或者 thinking,都收拢在展开收起卡片里。
>   当有了 done 信号之后,输出的平台文本内容才会显示到卡片外面,但如果有工具调用啥的,
>   还是会收到卡片里。一旦某一个有了 todowrite,就收起之前的卡片,新开一个卡片里面
>   开始 todo 相关的渲染逻辑和规则。」

> 「如果有了 todowrite,不用第二张卡片,继续第一张卡片里继续输出就行了,因为此时肯定是
>   没 done 信号的…卡片外面也没文本…会出现两张连起来的卡片,不太好。」

### 现行三条

1. **done 之前:一切都在卡片里** —— 工具调用、普通正文、thinking 一律收进当前 sink
   (有 todo 就进当前那条 todo,没有就进壳)。
2. **done 之后:只有正文出卡片**;之后若还有工具调用,仍然收进卡片 —— 它是过程不是回答。
3. **卡片之间的边界由「卡外落过东西」决定,不由清单决定** —— 一轮正常跑完就是**一张**
   过程卡;只有 done 之后 agent 又开新计划继续干时,才在结论下面另起一张。

### 被推翻的两条,以及为什么

- **「还没有 todo 时正文落壳外」**:`ensureShell` 在循环开头就把壳压进了 `blocks`,
  于是开场白排到了**整张卡之后**,还和 done 之后的结论粘成一段。用户真机截图指认:
  「这个话怎么感觉是在创建 todo 之前的?…那么这段话应该在展开收起的卡片之前才对呢?」
- **「一出现 TodoWrite 就收起前一张、新开一张」**:两张卡之间**永远不会有东西隔开** ——
  卡外唯一会出现的内容是 done 之后的结论,而 TodoWrite 必然在 done 之前。所以那条规则的
  产物一定是两张紧贴的卡:两个「已完成 + 秒数」的头,说的却是同一段连续过程。
  它还制造过两张卡头**显示同一个耗时**的坏画面(thinking 事件不带时刻,前一张只能
  退回轮次跨度)—— 陈列页的端到端格照出来过。

### 连带必须做的两件事(不做会把答案埋掉)

- **兜底提结论**:整轮没发 done 时,轮末把当前 sink 里最后一段**回答**提到卡外。
  没有这条,一个「只答话、不调工具、又没发 done」的普通回合会被整段埋进默认收起的抽屉,
  用户看不到自己问题的答案。
- **`ShellText` 加 `thinking` 标记**:兜底**不许提 thinking** —— 提出来就是把
  「想什么」当成「答什么」。踩过一次:整轮只有一句 thinking 时它被提到壳外、
  壳空掉后整张壳被丢,「思考中」那一格直接没了。
  连带:`pushInside` 的合并判据要认「同一种文字」,thinking 和回答挨着时必须分成两段。

### 历史基线

`historical-turn-baseline.json` 已按最终裁决重刷,四处变化逐条核过(见
`done-marker-key.test.ts` 的注释)。其中一处是**修复**落进基线:旧基线里
`bare-done-after-todos-closed` 有一条**重复的 todo 行**(3 行只对应 2 条 segment),
正是用户指认的「为什么有两个一模一样的 todo」—— 上次修它时没有同步重刷基线,
于是这条测试在 HEAD 上**本来就是红的**。基线一旦欠着就从守护栏退化成噪音。
